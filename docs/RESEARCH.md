## 2. Playwright

```bash
npm install
npx playwright install chromium
npm run research:inventory
```

Результат: `research/output/inventory.json` и снимки всей страницы в четырёх viewport. Каталог исключён из git — нельзя случайно публиковать сторонние изображения, cookie или персональные данные. Не логировать токены и POST тела форм. Если сайт не отвечает, записать ошибку отдельно и повторять с паузой, не нагружая сервер.

Дополнительно снять отдельно состояния меню, модальных окон, квизов и скролл-анимаций, сохранить source date + viewport + браузер. Для полноты составить state graph по каждому квизу.

## 3. REA

Документация: https://github.com/morluto/rea/blob/main/docs/browser-observation.md

```bash
npx rea-agents setup
# После настройки/перезапуска агента изучить:
rea --help
rea list-browser-targets --help
rea inspect-web-page --help
```

Запуск Chrome с CDP (изолированный одноразовый профиль):

```bash
google-chrome --remote-debugging-port=9222 --user-data-dir=/tmp/rea-dvizh-observe 'https://xn-----6kcbablcjk5dhfd3bbeb0ep8fwag6n.xn--p1ai/'
rea list-browser-targets http://127.0.0.1:9222 --json
```

Дальнейшую команду наблюдения брать из **установленной** версии REA и фактически возвращённого target ID. Исследовать публичные ресурсы и события. REA не даёт доступа к внутреннему серверному коду.

### Матрица наблюдений

| Сценарий | Действие | Проверить |
| --- | --- | --- |
| Навигация | Клик по якорю | Фокус, URL, смещение, sticky header |
| Квиз | Выбор каждого варианта | Следующий шаг, ветвления, прогресс |
| Квиз | Назад | Сохранение предыдущего ответа |
| Форма | Незаполненные поля | Валидация, сообщения |
| Форма | Корректный ввод **без отправки** | Состояние кнопки, политика согласий |
| Окно | Открытие / закрытие / Escape | Overlay, scroll lock, focus |
| Мобильный | Открыть меню | Точки перелома, анимация |

## 4. Отчёт

Каждое наблюдение оформлять как `OBS-ID / URL / viewport / action / outcome / screenshot / console / confidence`. При недостатке данных писать «не проверено».
